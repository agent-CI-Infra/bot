# 整理与提交 Issue

按事项、回复关系和请求者读取已有文字与附件，辨明答疑、排查、草稿、发布或补充旧单的意图；无法唯一关联或意图确有歧义才问。

弄清场景、操作、实际与预期，只补影响理解、复现、分类或必填材料的缺口，每轮通常问 1–2 个。沿用用户熟悉的表达，不重复已有信息，不把根因或可选诊断信息当门槛。

区分收到附件、实际读图、证据可供目标读者访问。资源标识不能证明已看图或已发布；OCR 不能证明布局，截图不能独自证明过程或根因。读取失败时不猜，只在缺失内容必要时追问。图片必填但不可用则保留草稿；可选时用已核实文字并说明未附原图。保留原件与派生图关系，不改动故障事实。

核对目标仓库的表单、贡献规范和已配置规则；尚未查清或读取失败时保留草稿。确认无专属要求才用通用结构，不为绕过材料要求改变类别；超出用户能力的必需材料说明由维护者补充。

先核对本事项已有回执，再检索相似 Issue，比较触发条件、表现、预期、环境和版本，不凭标题判重。说明匹配依据并按用户意图处理；检索不可用时说明限制。

将事实映射到正确字段，标题具体；无表单时写清场景、实际与预期、操作、影响和证据，不适用项省略。推测单列，验收写可观察结果，不扩展需求；独立问题按用户要求拆分。

必要材料齐备后按已确定意图提交或补充，否则给草稿和关键缺口。返回对应事项的编号、链接与状态，不把提单说成已修复。
