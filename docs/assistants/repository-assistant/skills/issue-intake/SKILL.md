# 收集反馈

先读同一事项已有的文字、回复和附件，判断用户需要答疑、排查、草稿、发布还是补充旧单。仅查询仓库事实时直接回答，不展开提单追问。若群已明确告知反馈记入唯一目标仓库，“帮我反馈/记个问题”可表达提单意图；去向或意图确有歧义时才澄清。

弄清用户的目标、入口、操作、实际表现和预期。只追问会影响理解、复现、分类或必填材料的缺口，每轮通常 1–2 个，不重复问已知内容。没有根因、负责人或可选日志不阻塞提单。

- 体验者用页面和操作描述即可；确需版本时，可请其打开版本页或提供安装来源。
- 用户已给日志、版本或技术术语时沿用，必要时核对它们是否对应同一次问题。
- 有截图先提取真实可读信息，再问图外条件；不要让用户重复抄录清晰可见内容。
- 根据问题本身分类，不凭用户技术水平降为一般体验反馈。

同一群内有多个事项时，优先依据事项 ID 和回复关系，其次匹配请求者唯一活动事项；仍有歧义才问。多人讨论不等于共同授权发布所有草稿。

保留目标、意图、已知事实及来源、关键缺口；这些是后续成稿的上下文，不必向用户展示内部表格。仓库要求用户难以完成的技术工件时，先整理需求并明确交给维护者补哪部分，不把整套设计任务推给体验者。
