# 服务角色

Bot 里的角色分两个维度：

- **工作角色**：每个项目各自的 Manager、Dev、QA、Reviewer 等，在项目的「角色」页配置，见 [Role-Pool](role-pool.md)。
- **服务角色**：平台级的助手，不属于某个项目。内置两个：`management-assistant`（管理助手，用于控制台管理对话和飞书个人私聊）和 `repository-assistant`（仓库问答助手，群聊的默认推荐角色）。超级管理员还可以新建自定义服务角色。

服务角色在「全局设置 → 服务角色」（`#/settings/service-roles`）维护，只有超级管理员可以查看和修改。

## 定义

每个服务角色有名称、职责说明、提示词、模型、权限、可选预算和配置版本（revision）。

- **模型**只能从部署共享模型（不属于任何仓库的模型）中选择。没有配置模型时，这个角色的对话直接提示到控制台配置，不会改用某个项目的模型或其他模型。删除共享模型时，用到它的服务角色改为未配置模型。接入向导设置默认共享模型时，还没有模型的内置角色同时采用它；已经选了模型的角色不受影响。
- **提示词**附加在内置安全提示之后，只是行为说明，不能扩大工具或权限。
- **权限**和工作角色共用同一目录、保存校验及执行策略，页面按「平台能力 / GitHub」分组，具体权限矩阵见 [共用角色权限](role-pool.md#shared-role-permissions)。管理助手固定允许全部已接入能力（`permissions_fixed: true`），仍与当前用户有效权限和项目范围取交集；群聊角色可逐项配置。仓库问答助手默认 GitHub 各资源只读，不使用虚拟电脑、不指派其他角色、不访问其他角色的任务或修改共享平台配置；把某项 GitHub 资源改成读写后，它可以用 `github_write` 写本群范围内的仓库。管理助手同样提供 `github_write`，只写当前用户能写任务（`tasks.write`）的仓库。自己的任务、当前会话记录、私有记忆和已绑定技能不再单独配置。旧文件/命令混合设置及只允许部分 GitHub 动作的配置显示「待迁移：保留原有操作」，不会自动扩大成整个资源的读写。
- **预算**是可选的累计上限 `{currency, limit_amount}`，语义与项目管理预算 `management_budgets` 相同：累计费用达到上限即停止；存在无法计价的用量（已结束但没有费用的请求、其他币种的费用，或当前模型没有该币种的价格）时也停止，不把未知费用当作零。

内置角色可以修改，但不能停用或删除；自定义角色可以停用和删除，但仍有启用中的群聊绑定时不能删除（409 `service_role_in_use`），需要维护人先为这些群更换角色或停用绑定。每次保存都要带上读取时的 `expected_revision`，版本已变时返回 409 `service_role_revision_conflict`，不会覆盖别人的修改。新建、修改、删除和模型的自动采用／清除都写入审计记录（`service_role.*`）。重启不会覆盖管理员对内置角色的修改。

`project_tasks` 控制访问和修改范围内其他角色的任务。`delegation` 只控制把工作交给其他角色；群聊通过项目 Manager 派活，不直接指定执行角色。旧群聊派活配置附带的查找、追加说明、修改任务契约和取消权限保留为待迁移的原动作集合，选择新等级后由新权限分别控制。任务操作仍使用管理服务的版本检查、幂等及实时授权。

允许使用虚拟电脑的服务角色使用自己对话归属的助手电脑（见下文「助手电脑」），不再借用项目电脑，也不需要先选仓库；使用前提是群的授权者或私信本人至少在一个范围内仓库有 `tasks.write`。私有记忆按角色、会话、用户或群绑定和授权围栏密封保存；复用同一角色模板不会共享不同群或用户的历史、任务或记忆。管理助手和群聊助手均可使用已接入的仓库读取、管理查询/命令、私有记忆和电脑工具，权限之外仍受各入口支持范围约束。

## 助手电脑

群聊助手和管理助手的 `read_file`、`write_file`、`delete_file`、`run_command`（以及附件的 `import_message_resource`、`attach_workspace_file`）使用按对话归属分配的助手电脑（#457）：群按群（飞书连接 + 群），私信按人（会话所属组织 + 本人），同一个人的飞书私信和控制台管理助手对话（同一范围）共用一台电脑和一个 HOME。归属、授权围栏和 HOME 代次都由控制面根据已认证的会话决定，模型只给路径，不能指定电脑、卷或宿主路径。部署没有挂载 HOME 卷（`assistant-homes`，控制面的 `BOT_ASSISTANT_HOMES`）或没有 manager 时，不提供这些工具。

- **电脑**：manager 在宿主 Docker 上创建的同级容器（`manager/assistant-computers.mjs`），用批准的项目电脑基础镜像（不含任何项目的软件包、环境变量和初始化脚本，`BOT_ASSISTANT_IMAGE` 可另指定），uid 10001、只读根文件系统、去掉全部 capabilities、`no-new-privileges`、init，每台默认 1 CPU、2048 MiB 内存（含 tmpfs）、512 个进程，**没有网络**，用 Docker 的默认运行时（runc）。CPU、内存、进程数、`/tmp` 和工作目录大小在「全局设置 → 助手电脑」修改，范围与项目电脑相同；新值用于之后创建的电脑，空闲的电脑在归属的下一个回合开始时按新值重建（HOME 保留，`/tmp` 和工作目录清空），进行中的回合不受影响。不在容器里嵌套其他沙箱，创建失败时工具明确返回 `assistant_computer_unavailable`，不改在项目电脑或宿主上执行。
- **目录**：`~`（`/home/assistant`）是持久 HOME；工作目录 `/workspace` 和 `/tmp` 是 tmpfs（默认各 512 MiB，内容计入内存上限，写满时命令得到“磁盘已满”），可以运行放在里面的程序，随电脑删除。pip、uv、npm 的缓存指向 `/tmp`，用户级安装（`pip --user`、`uv tool`）仍在 HOME。提示词要求临时文件写 `/tmp`，只有值得以后复用的数据才写 HOME；群的 HOME 由本群现有和以后加入的成员共用。
- **生命周期**：一个回合第一次运行命令或读写 `/tmp`、工作目录时创建（或复用）这台电脑；只读写 HOME 的回合和没有命令权限的回合不启动电脑，由控制面直接读写 HOME（打开文件后按 `/proc/self/fd` 核对真实路径在本归属的目录内，只接受普通文件，符号链接和 `..` 一律拒绝）。回合进行中（含模型思考和其他工具）控制面每 30 秒续期；最终回复交出、回合失败或被停止后，结束本回合启动的全部进程，开始空闲计时（默认 5 分钟），期间同一归属的新回合直接复用，`/tmp` 仍在。空闲到期、最长存活（默认 4 小时，只在两个回合之间检查）、授权围栏变化（群的成员、绑定、角色权限或授权人权限变化；个人的授权版本变化）、绑定停用都会立即删除电脑；续期中断 2 分钟（控制面崩溃或卡住）也会删除。manager 启动时删除上次留下的全部助手电脑，控制面启动后第一次对账删除不属于正在运行回合的电脑；回合在电脑创建完成后才算持有它，所以正在创建的电脑被这次对账删掉时，回合重新核对权限后再取一次，不因此失败；权限或会话来源已经变化的回合在这次核对时结束，不会重取。同一归属同时只有一个回合使用电脑；同一个人在私信和控制台同时用电脑时，后来的回合等前一个结束。同时存活的电脑达到上限（默认 20 台）时，先删最久未用的空闲电脑，都在使用时按到达顺序排队，排队开始时向对话发一条进度消息。
- **HOME 代次**：HOME 存在 Compose 卷 `assistant-homes` 的 `<归属>/home-<代次>`，电脑只挂入当前代次（卷 subpath）。绑定换成另一个、服务角色更换、可访问的仓库范围缩小（群：仓库移出绑定或授权人失去权限；私信：本人失去某仓库权限）时开始新代次，旧代次封存、不再挂载，封存满保留期后删除；范围扩大、修改提示词或权限项、群成员变化都不换代。
- **容量与保留**：每个回合结束后统计 HOME 的大小和文件数；超过上限（默认 5 GB）时下一回合以只读挂载，工具结果提示模型用 `delete_file` 清理或请管理员在控制台清空，清理后下一回合恢复可写（软上限：单个回合内仍可能写超）。最后一个回合结束后超过保留期（默认 30 天）没有新回合，删除这个归属的全部数据。所有 HOME 合计没有硬上限，超过告警值（默认 50 GB）时在「全局设置 → 助手电脑」和日志中告警。这些值都在「全局设置 → 助手电脑」修改，那里也列出每个 HOME 的占用并可以清空。
- **已知限制**：电脑没有网络，不能在线安装软件包；HOME 里的 `.pth` 等配置会在本归属以后的命令中生效（git 不读 `~/.gitconfig`），影响只限本归属，可以在控制台清空。

## 阶段消息与一轮回答的结束

服务角色的每轮回答（管理助手的一条消息、群聊助手的一次回答，以及会话定时任务的一次运行）默认带有 `send_message` 工具（#435），用来在工作期间向当前会话发送阶段消息。它不是权限项，也没有审批。系统提示词和工具说明告诉模型何时发送（#453）：预计要较长时间的工作（多步工具调用、跨仓库或多文件检索、日志排查、在电脑上执行命令）开始前，先发一条说明接下来要做什么；之后只在有关键发现、新证据或阶段结论时再发；不发「仍在执行」「请稍候」这类没有内容的消息，也不在最终回答里重复已发过的进展；可能安静结束的回合（群里没有 @ 助手的消息、没有可汇报内容的定时任务）在确定要回答之前不发。

- 每轮最多 10 条，回合每并入一条新消息（见[消息渠道](message-channels.md#回合中收到新消息)）再多 1 条。超出后的调用不发送，返回 `stage_message_limit`（`remaining: 0`），本轮继续，由最终回答给出结论。系统提示词、工具说明和每次调用的返回值（`sequence`、`remaining`）都向模型说明这个上限。
- 只发文字（Markdown，最多 4000 字），发送前脱敏。附件只随最终回答发送。最终回答仍是模型不再调用工具时的那次回复，由系统在本轮结束时发送。独立任务不提供这个工具。
- 发送途径与最终回答相同：飞书私聊、群聊和定时任务在轮次运行期间立即写入发送队列，发送前复核源消息、绑定、授权和围栏；控制台管理对话写入事件流，按顺序显示在最终回答之前。细节见[消息渠道](message-channels.md#阶段消息与停止回答)和[统一管理服务与管理对话](management-agent.md#会话停止和执行)。

一轮回答没有步数上限，只在以下情况结束：模型回复时不再调用工具；回答被停止（管理助手由用户停止；群聊助手在源消息撤回、绑定或围栏变化时停止，也可以在控制台停止）；或者服务角色配置了预算且预算用完（每次模型请求前检查）。上下文大小由工具结果的折叠控制，见 [Agent 运行时](agent-runtime.md)。

## 独立任务

管理助手和群聊助手都可以创建和继续自己的独立任务：为了保持当前对话整洁，把一件事放到单独的上下文里想清楚，只把结论带回当前回答。独立任务不受权限项控制，也没有配置项；它使用与当前对话相同的服务角色、模型、预算和工具，权限也相同（管理助手是固定全权限与当前用户有效授权的交集，群聊助手是服务角色权限、绑定范围和授权者当前权限的交集），不能扩大权限，也不能再开新的独立任务。

- 工具：`start_own_task`（标题、要想清楚的问题）、`continue_own_task`（编号、补充说明）、`list_own_tasks`、`read_own_task`、`manage_own_task`（暂停或取消；暂停后可以继续，取消后不可继续）。
- 归属：管理助手的独立任务属于同一用户的同一个管理会话，群聊助手的属于同一条群绑定。授权修订（管理助手）或群围栏变化（绑定、角色权限、授权者权限）之后，旧的独立任务不再可见，也不能继续。
- 每次运行不限步数（每步的工具调用数量也不设上限，结果预算与所在对话相同），每个独立任务也不限轮数：一次运行在给出结论、被暂停或取消、所在对话被停止或服务角色预算用完时结束。每轮的说明和结论密封保存在 `service_role_own_tasks`，不进入 `tasks` 表，也不出现在项目看板；继续时较早的轮次合计超过 96 KiB 就从最早一轮开始略去并注明略去轮数，`read_own_task` 仍能读到全部轮次。独立任务不向会话发阶段消息。服务重启时运行中的独立任务记为失败（`own_task_interrupted`），已有结论保留。
- 用量与所在对话一样记在服务角色上（`repository_id` 为空），受服务角色预算限制。控制台管理对话把独立任务和其中的查询、命令显示为执行步骤。

## 用量与计费

服务角色的模型请求记在 `model_requests.service_role_id` 上，`repository_id` 为空，不计入任何项目。项目的统计、成本和管理查询 `get_usage` 仍只按项目汇总；服务角色页按角色显示累计请求数、token、费用和未计价请求数。删除自定义角色后，已有记录仍保留原角色 id。

`model_requests.repository_id` 原来是 `NOT NULL`。升级时控制面重建一次这张表：沿用表原有的建表语句（含之后新增的全部列），只去掉这一处 `NOT NULL`，复制全部数据，并按原 SQL 重建全部索引和触发器；完成后在设置项 `model_requests_nullable_repository` 记录时间，之后启动不再重建。

## 管理助手

控制台管理对话和飞书个人私聊都使用 `management-assistant`：模型、预算和用量都属于这个服务角色，不再取账户可读的第一个项目。账户第一个项目没有配置模型时，问候仍然正常。权限仍是当前用户自己的有效权限，项目范围和工具与 [统一管理服务与管理对话](management-agent.md) 一致。

## 群聊助手

一个飞书群绑定一个服务角色和一份项目范围（整个组织或多选仓库），由对所选仓库有配置权限、已绑定飞书且在群中的维护人在「身份与权限 → 飞书群聊助手」设置。同一个服务角色可以绑定到多个群，每个群的项目范围各自独立。群内有效权限是服务角色的权限项、绑定范围和授权者当前权限三者的交集，不校验发言人。群聊助手使用服务角色自己的模型和预算，用量记在服务角色上；控制台「查看连续会话」显示本群的回答和用量。具体规则、工具和旧群员工迁移见 [消息渠道](message-channels.md#群聊助手绑定)。
