# 管理助手、飞书应用机器人与群聊助手

launchpad 提供面向管理员与团队成员的对话式协作能力：在 Web 控制台和飞书私聊中使用 **管理助手**，在飞书群中使用 **群聊助手**。底层管理服务与渠道架构见 [统一管理服务、服务角色与飞书渠道架构](../design/assistants-and-channels.md)。

## 1. 管理助手（Web 控制台与飞书私聊）

- **入口**：控制台侧栏「管理助手」（全部项目 `#/management` 或单项目 `#/projects/<id>/management`）以及已绑定的飞书机器人私聊，两者共享同一套管理引擎、工具目录、模型与个人权限。
- **能做什么**：
  - 跨项目自然语言查询任务、运行日志、用量、审计与仓库代码（无需先选项目或记命令前缀）；
  - 修改项目设置、Manager 协作流程（修改前先展示前后对比流程图并等待确认）、角色配置、新建/暂停/重试/取消任务，以及按权限查询和配置全局/单项目虚拟电脑预装工具、触发或停止预编译镜像构建；
  - 完成新仓库接入分析与启动/启动申请；
  - 使用个人专属的短时 **助手电脑**（内置 Chromium、桌面工具与图片处理库；默认 16 GB 内存，在内存更小的宿主机上自动收紧至安全上限，`/workspace` 与 `/tmp` 各默认 20 GB 临时磁盘卷应用层软限额并受宿主机数据盘余量门禁保护）拉取已授权仓库完整源码（通过受控 `checkout_repository` 工具复用控制面 Git 缓存，或在 `pi`/`claude_code`/`codex` 后端中直接 `git clone`/`gh` 按需换取单仓短期只读凭证）执行构建、测试与分析，以及创建不打断主对话的独立子任务；
  - 在部署启用助手电脑（`manager` 与 `assistant-homes` 卷）且当前用户具备助手电脑使用资格（超级管理员、存在待接入仓库的管理员，或在至少一个已授权项目具备任务写权限）时，可在个人持久 `HOME` 目录的 `~/memory/` 下以自由 Markdown 文件记录、检索、更新与清理跨会话私有长期记忆（跨飞书私聊与 Web 控制台所有会话共享，其他用户与群聊不可见；可通过 `list_files`/`read_file`/`write_file`/`delete_file` 直接操作，无需冷启动容器；仅具备项目只读权限的用户不提供助手电脑与私有记忆文件工具）。
- **阶段消息与随时停止**：耗时较长的调查会自动发送阶段进展消息（每轮最多 10 条），回答实时流式输出，支持 Markdown、代码复制与 Mermaid 流程图；随时可点击「停止」中止后续调用。在飞书私聊中创建的项目任务完成后，结果卡片会自动回传到原私聊。
- **执行进展实时可见**：「执行进展」逐条列出这一轮的步骤。助手用 Pi 后端时，它自己在助手电脑上做的事也会实时出现：执行命令、读写或搜索文件的步骤先显示「正在电脑上执行 `命令首行`」，结束后显示耗时，命令失败时显示退出码，展开可看到输出末尾几行；每次请求模型、压缩会话上下文、模型拒绝图片后去掉图片继续、请求被修改后重新开始也会提示；这一轮只有这类提示、没有步骤时，「执行进展」照样显示，摘要写「n 条提示」。回合进行中，标题旁显示「最近活动 x 秒前」，长命令运行期间可据此判断助手仍在工作。命令行和输出里的凭据（已知令牌、`ghp_` 等格式化令牌、`TOKEN=…`、`--password …`、`Authorization: Bearer …` 等）在显示前遮盖；步骤很密时部分步骤会合并为一条「另有 n 个电脑步骤未逐条显示」。飞书会话页「查看执行过程」和群聊助手的步骤记录同样列出这些步骤名称。
- **权限边界**：管理助手严格在当前用户自身有效权限内执行，授权范围内直接生效，无冗余审批。
- **可读操作回执**：对话卡片与回执详情页用当前用户名称和仓库 `owner/name` 说明发起人与项目；创建任务显示请求摘要，配置版本只说明是否变化。原始 ID、完整哈希和参数指纹仍保留在「原始事实与回执」与原始 JSON 中，幂等及并发校验不变。

## 2. 飞书应用连接管理

控制台提供全平台应用（仅超管）与组织专属应用（组织管理员或该组织任一仓库管理员可新增企业自建长连接应用；仅限本组织可见与使用，经其绑定的身份与群严格限定在本组织内）：

- **管理入口**：超管在「全局设置 → 飞书连接」（`#/settings/feishu`），组织/仓库管理员在「个人设置 → 组织飞书应用」（`#/identity/feishu-apps`）。
- **新建与日常管理分离**：
  - **3 步新建向导**：填写应用凭据并一键复制完整权限 JSON → 按引导订阅事件（`im.message.receive_v1`、`im.message.recalled_v1`、群成员与解散事件等）与新版卡片回调（`card.action.trigger`）并发布版本 → 完成检查并跳转绑定。
  - **已建应用管理详情页**：分区展示实时中文连接状态与自动权限检查、凭据与启停配置、可折叠配置指南、收发健康诊断与「查看该应用的飞书会话」（`#/conversations?connector=<id>`）快捷入口，以及二次确认删除连接（停用关联绑定/定时任务，历史聊天记录只读保留；重连同一应用自动恢复未解散的会话）。本地消息检索、显式重同步可见历史与超管按会话保留/清理均统一收口在「飞书会话」页。

### 飞书所需应用权限清单

以下权限清单由服务端 `src/channels/feishu.ts` 的 `FEISHU_SCOPES` 唯一维护，向导导入 JSON、详情页配置指南和自动权限检查均从此生成（企业自建应用包含全部 15 项，商店应用不含标注「企业自建」的 2 项）：

| 权限 | 用途 |
| --- | --- |
| `im:message.p2p_msg:readonly` | 接收用户私聊消息 |
| `im:message.group_at_msg:readonly` | 接收群内 @ 机器人的消息 |
| `im:message:send_as_bot` | 以机器人身份发送消息、发送和更新交互卡片 |
| `im:resource` | 获取与上传消息中的图片和文件；已有连接也需导入完整权限并发布生效 |
| `im:message.reactions:write_only` | 在正在处理的原消息下添加表情，回复送达后删除 |
| `cardkit:card:write` | 创建与更新卡片 |
| `im:message.group_msg` | 接收群内用户消息，并满足群历史读取接口的额外权限要求；不包含其他机器人的实时消息 |
| `im:message.group_msg.include_bot:read` | 企业自建应用接收群内用户及其他机器人的消息，不推送本机器人自己发送的消息；商店应用不申请 |
| `im:message:readonly` | 读取机器人所在会话的可见历史及接收撤回事件 |
| `im:chat:read` | 查看群信息，订阅群解散事件 `im.chat.disbanded_v1` |
| `im:chat.members:bot_access` | 接收机器人进群、移出事件 |
| `im:chat.members:read` | 判断当前 bot 是否在群中并完整分页核验维护人及来源成员；保存群聊助手绑定时必需，缺少时保存返回 `channel_audience_permission_required` |
| `contact:contact.base:readonly` | 调用通讯录用户资料接口；与姓名字段权限一起开通并发布，通讯录可见范围须包含本人 |
| `contact:user.base:readonly` | 读取已绑定用户的飞书姓名；需发布生效，通讯录可见范围须包含本人 |
| `tenant:tenant:readonly` | 企业自建应用自动获取安装 tenant_key；保存连接前需开通并发布生效 |

> 权限补齐后必须在飞书开发者后台 **创建并发布新版本**，再回到控制台刷新权限状态。

## 3. 个人双端身份绑定

在「个人设置 → 飞书绑定」（`#/identity/feishu`）以「飞书身份绑定 / 飞书群聊助手」上下两张清爽卡片分别管理个人绑定与群绑定（不依赖 GitHub OAuth，本地账号同样可用）：

1. 在「飞书身份绑定」卡片点击「创建个人绑定」，选择可见机器人并点击「生成绑定串」，得到一次性 `绑定 FSB-...` 消息（5 分钟有效）。
2. 打开对应飞书机器人私聊，原样发送该消息即可完成双向验证并收到绑定成功回执。
3. 已解绑或过期的历史记录自动折叠在「历史绑定记录」中；解除绑定需二次确认。
4. 私聊固定指令仅保留：`绑定`/`/bind`、`确认绑定`、`解绑`/`/unbind`、`身份`/`/identity`、`重新认证`/`/reauth`；其他所有消息均作为自然语言交给管理助手。

绑定只证明身份归属，不增加任何项目权限。

## 4. 群聊助手绑定与三维权限

将飞书机器人拉入群后，具备目标仓库配置权限且在群中的维护人在「个人设置 → 飞书绑定」点击「创建群绑定」或对应群的「配置群聊助手」进入独立群配置页（`#/identity/feishu/groups/new`、`#/identity/feishu/groups/<chat-id>`）一页完成配置（首个配置者成为群负责人；组织管理员和超管也可维护、停用或转交负责人，已停用群绑定自动折叠在「已停用的群绑定」中）：

- **仓库范围、模型与提示词**：可绑定整个组织或多个仓库，并直接在群配置页选择本群所用模型、填写提示词与职责说明（最多 35,000 字，支持快捷填入默认问答提示或从已有群复制配置，按值填充后各群独立演进）以及在高级设置中切换 Agent 后端（默认 `pi`）。群所用模型按当前范围实时筛选，必须对范围内所有仓库均可用（单仓库群可选用该项目的专属模型或已授权共享模型；多仓库或整个组织群选用覆盖全部范围的共享模型；若组织群选用了受限共享模型且后续该组织新增了未授权仓库，群会按失败关闭暂停并提示补齐授权或更换模型；尚无已启用项目的空组织仅允许选用对全部项目可用的共享模型）。
- **参与方式**：可选「仅回应 @」「回应 @、提问或求助」「读取每条新消息由助手决定是否发言」。在非 @ 场景下，若无需插话助手会调用 `stay_silent` 保持安静。
- **三维独立权限**（表单直接展开，附常用快捷填充）：
  1. **GitHub 权限**：只读（`read`，默认）、Issue/PR/Actions 读写（`comment`，可评论、打标签、提 Issue、触发工作流）、逐项设置（`custom`，可按需单独开启 Contents 写）。
  2. **项目任务权限**：不可访问（`none`，默认）、只读（`read`）、只读 + 可新增（`create`，经项目 Manager 派活，可给本群建的任务追加说明或取消，任务结束后结果自动回群）、完全可读写（`write`）。
  3. **平台能力**：项目共享知识（新建默认只读，可调不可访问/读写）、项目设置与角色配置（默认不可访问）、项目定时与通知（默认不可访问，**不影响本群自己的定时任务**）。
- **默认内置能力**：部署启用助手电脑（`manager` 与 `assistant-homes` 卷）时，所有已启用的群绑定默认允许使用本群专属 **助手电脑**（可在具备 Contents 读权限时通过 `checkout_repository` 或容器内 `git`/`gh` 动态只读凭证拉取群范围内仓库源码到 `/workspace` 或 `/tmp` 进行构建与验证，并在本群持久 `HOME` 的 `~/memory/` 下以 Markdown 文件维护按群隔离的长期记忆，换模型、改提示词或扩大范围不丢记忆，仅仓库范围收缩或换绑时自动封存旧代次）；同时支持在群内直接管理 **本群会话定时任务**。
- **生效边界与统一 Bot 身份**：群内最终权限 = 群绑定权限 ∩ 仓库范围 ∩ 授权人当前有效权限 ∩ 各项目能力上限 ∩ GitHub App 安装权限。群聊助手与管理助手均属于同一 launchpad 平台 bot 体系，无论是直接写 GitHub 还是派发项目团队开发提 PR，都统一使用对应仓库配置的 GitHub bot 账号；回答能力与权限边界时会结合群权限与各项目的能力上限（例如仅当群可派活且目标项目能力上限为「可开发并开 PR」时才可发起开发任务提 PR）用自然中文说明，不暴露内部权限键名。群内所有成员按此绑定统一使用助手，不核对单个发言人的平台账号；平台不会在绑定或改配置时主动往群里发广告或能力名片。

## 5. 日常交互体验与飞书会话管理

- **处理中表情与回合消息并入**：私聊消息和群内被 `@` 的消息会自动贴上 `Typing` 表情并在答复送达后移除；助手思考或执行工具期间新到达的消息会自然并入当前回合上下文，不打断运行。
- **富文本、丰富交互卡片、图片与文件**：日常回复默认使用原生富文本 Markdown（`post`）并自动分段；飞书私聊管理助手、群聊助手及对应会话定时任务均内置通用的 **Card JSON 2.0 构卡与交互能力**（`set_feishu_card` + 内置 `feishu-cards` Skill），不绑定特定业务场景，由助手按内容特点自主选用——支持主题色标题栏、多列布局、折叠面板、原生表格（`table`，含分页与首列冻结）、VChart 图表（`chart`）、安全跳转按钮，以及由控制面托管的多视图切换、分页筛选列表与受控后续触发按钮（点击通过 `card.action.trigger` 原地更新卡片或以点击人身份发起后续回合，14 天内有效）；卡片若被飞书接口拒绝会自动优雅降级为原生 Markdown 富文本，不丢消息。同时支持解析入站图片、文件、富文本与交互卡片，并可在助手电脑处理后作为附件发回群/私聊。
- **飞书会话页（`#/conversations`）**：支持按飞书应用筛选（`#/conversations?connector=<id>`），按会话权限查看本人的私聊与有权管理的群聊本地历史、检索本地消息、管理本会话的 **定时任务**（从「飞书绑定」点击「定时任务」直达 `#/conversations/<chat-id>?section=schedules` 并自动展开）、查看每轮执行步骤与派生任务；具备同步权限的维护人或超管可发起显式可见历史重同步；超级管理员可按会话配置本地消息保留天数（1–3650 天或长期保留）与显式清理指定时间之前的历史；群负责人/管理员可直接在页面点击 **「停止回答」** 中止正在运行的群回复。
- **管理助手与助手电脑配置（超管）**：在「全局设置 → 管理助手设置」（`#/settings/management-assistant`）配置平台级管理助手的名称、职责、提示词、Agent 后端、部署共享模型及查看累计用量。管理助手和群聊助手默认使用 `pi` 后端（升级时，已保存为 `native` 的管理助手和群配置会一次性改为 `pi`；`native` 仍可手动选择），日常体验与 `native` 一致：控制台边生成边显示回答，回合中的新消息并入当前回合，被编辑的消息按新内容作答，定时任务和群里不需要回答的消息可以安静结束；区别是每轮都在该会话的助手电脑上运行（Codex、Claude Code 后端也是）：回合一开始就申请电脑，空闲电脑默认保留 30 分钟，同一人或同一群在这段时间内再问会直接复用，不再等冷启动；部署缺 manager 或 `assistant-homes` 卷时，选择后端处和「助手电脑」设置页会说明原因，控制面启动日志也会警告，不必等到轮次失败才发现。在「全局设置 → 助手电脑」统一配置空闲回收时长、存活上限、容器资源、外网开关及各归属 HOME 的空间占用与清理。
