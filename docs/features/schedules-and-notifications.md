# 定时任务与事件通知订阅

launchpad 区分 **项目定时任务**、**飞书会话定时任务** 与 **事件通知订阅** 三类定时/异步通知能力，职责清晰分离。底层调度与 Outbox 引擎设计见 [持久化调度与事件通知引擎](../design/schedules-and-events.md)。

## 1. 两类定时任务的分工

| 类型 | 挂在哪里 | 执行者 | 结果去向 | 典型场景 |
| --- | --- | --- | --- | --- |
| **项目定时任务** | 项目的「定时任务与通知」页 | 项目 Manager / 项目角色团队 | 留在项目任务记录与 GitHub（如提 Issue、触发 workflow），**不发到飞书** | 每天 09:00 巡检 Nightly 指标并提 Issue；准点触发 `.github/workflows/nightly.yml` |
| **飞书会话定时任务** | 「飞书会话」详情页的「定时任务」折叠面板（从「飞书绑定」直达 `#/conversations/<chat-id>?section=schedules`，或直接对话管理） | 私聊管理助手 / 本群群聊助手 | 直接一次性回复完整最终结果到该私聊或该群（无中途进度播报；无异常时可保持沉默） | 每天早 8 点在群里发项目日报；定期检查 CI，仅失败时提醒 |

## 2. 项目定时任务

在「项目设置 → 定时任务与通知」创建和管理（首屏提供「项目定时任务」与「定时触发 workflow」常用模板，高级字段默认折叠）：

- **触发方式**：支持五段 Cron 或固定周期（带 IANA 时区与可选有效期），保存前实时预览未来触发时刻，支持暂停、恢复、编辑、删除与「立即运行一次」。
- **执行身份**：
  - **个人计划**：以当前用户自身项目权限运行，失权时自动暂停。
  - **项目服务计划**：由项目管理员或超管在高级选项创建项目服务身份（Service Principal）并指定维护人运行，不依赖创建人保持登录（创建人/维护人失权或委托撤销时自动暂停）。
- **报告型交付与允许创建 Issue 开关（`manager.check` / `schedule.due`）**：项目定时任务的交付终点固定为报告（不直接改代码或开 PR）。计划的 `file_issues` 开关可显式设为「允许」（即使执行角色无 GitHub 写权限也允许创建或回复本仓 Issue）、「拒绝」（即使角色有写权限也拒绝）或「跟随角色」；所有写入仍受项目能力上限（至少 `comment`）硬约束。
- **准点触发 GitHub Actions Workflow**：为避免 GitHub 自带 `on.schedule` 高峰期延迟或丢触发，可直接选用「定时触发 workflow」模板，让 Manager 按计划通过 `github_write` 调用 `workflow_dispatch`（要求能力上限至少 `comment` 且 App 具备 `actions: write`）。若同一计划上一次到期运行尚未结束，新到期会自动跳过防重叠。

## 3. 飞书会话定时任务

每个已绑定的飞书私聊和已配置群聊助手的飞书群都支持挂载多条会话定时任务：

- **管理入口**：
  - 控制台：在「飞书会话」（`#/conversations/<chat-id>`）展开「定时任务」面板，或从「个人设置 → 飞书绑定」对应个人/群条目点击「定时任务」直达（`#/conversations/<chat-id>?section=schedules`），支持五段 Cron 或 5 分钟–31 天固定间隔、时区预览、立即运行、暂停/恢复、二次确认删除与查看最近运行状态。
  - 对话直接管理：在私聊或已启用的群里直接用自然语言让助手查看、新建、修改、暂停、恢复或删除**本会话**的定时任务（与项目级定时权限相互独立）。
- **单次完整输出**：定时任务执行时不提供主动发消息工具（`send_message`），也不会在数据查询或助手电脑排队期间向飞书发送中途进度播报；助手会先完成全部数据拉取与核对，再一次性发出完整最终结果（文本或单张交互卡片）。
- **静默汇报**：在提示词中写明「没有异常就不发消息」时，助手检测到无内容可报会调用 `stay_silent` 记为「无需通知」，不打扰会话。
- **运行边界**：严格在私聊主人当前权限或群绑定权限范围内执行；解绑或群停用时自动暂停。

## 4. 事件通知订阅（发往飞书）

事件通知订阅面向实时告警，在项目「定时任务与通知」页配置（首屏提供「失败时通知」常用模板）：

- **支持事件**：`task.failed`（任务失败）、`ci.failed`（CI 失败）与 `ci.recovered`（CI 恢复，仅针对此前曾失败的运行）。
- **飞书目的地**：直接在编辑器中选择本人已绑定且可读本项目的私聊，或本人有权管理且范围覆盖本项目的飞书群；保存时自动登记，每次发送前都会重新核验绑定与项目权限。`list_schedule_destinations` 为每个目的地返回 `chat_id` 和 `name`（群名，或私聊对象的飞书名字；还没读到时为 `null`），管理助手按名称称呼会话，原样展示 `chat_id`，不当作密钥遮盖。
- **聚合、静默时段与预览**：支持配置聚合窗口（合并短时间内的同类事件）、IANA 时区与静默时段（静默期告警顺延发送），并提供「假设此刻收到事件」的预计发送时间预览。
- **发送记录与人工补发**：页面独立展示触发记录、通知发送明细与审计；网络波动会自动退避重试，结果不确定的项标记为 `unknown` 供人工核对后再决定是否显式补发。
