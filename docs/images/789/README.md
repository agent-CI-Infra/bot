# #789 看板刷新 404 的前后现场

三档宽度（390 / 768 / 1440 CSS px）的真实看板页面，只截 `#board-status` 那一行。同一条脚本、同一流程：

1. 起真实控制面，登录，打开 `#/board`，等第一页读成功（`共 0 项工作`）；
2. 让 `/api/board/cards?offset=0` 的后续静默刷新全部返回 404；
3. 等状态栏给出失败提示后截图。

- `before-*.png`：base `5a2acd4a` 的现场——`刷新失败，保留上次读取结果。可点击刷新重试。` 这句文案承诺「点击」，而 `#board-status` 没有任何按钮；此时请求已发了 2 次（首读 + 一次刷新），之后每 15 秒继续。
- `after-*.png`：本 PR 的现场——`看板刷新已停止：服务端返回 404。` + 真按钮 `重新读取看板`；请求停在 2 次，不再自动重试，点按钮才重新读取。

截图脚本：`shots789.mjs`（本地一次性脚本，未入库）；数据由 e2e `e2e/board-poll-retry.spec.mjs` 同一路径产生。
