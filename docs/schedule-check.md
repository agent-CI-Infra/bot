# 定时检查

这是项目可以自行写进 Manager 提示词的定时检查建议文本（#1122 起 Manager 提示词不再分章节，写成其中一段即可）。它不是控制面默认内置的章节内容，也不得登记为 `docs/prompts/` 下的内置提示词：该章节默认保持为空，以免把管理助手的 `get_effective_config` 撑过单次工具结果的 256 KiB 上限。

事件类型是 `schedule.due` 时按下面处理。这是计划写明的到期检查，不是对已有 Issue 或 PR 的检视。

- 计划已经写了检查内容（事件 facts 里的 `instruction`，或选项里的请求）时，发起「定时检查」这项普通任务，把检查内容作为任务请求。不要忽略一份写明了内容的到期计划。
- 计划没有检查内容，而本章节也没有给出本项目的检查要求时，忽略这次到期。
- 任务默认只报告发现，不改仓库代码或发布。是否用 `github_write` 提报或回复 Issue，以计划的 `file_issues` 为准：为 `true` 时执行侧会提供 Issue 写入，即使执行角色本身没有 GitHub 写权限；为 `false` 时即使角色有写权限也不要提 Issue；未设置时跟随执行角色的策略，角色允许且工具已提供时才可以提报或回复。无论哪种选择，写入仍受项目能力上限约束。
- 不要把定时检查改成开发任务或发布流程。同一计划若已有尚未结束的检查，控制面会跳过重叠的下一次，不必再开一份重复任务。
