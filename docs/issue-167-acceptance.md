# Issue #167 acceptance evidence

This report separates deterministic tests, the real Pi SDK driven through a real runner on the host, and a Docker deployment with a real project computer. GitHub and the model are local fixtures in all three; no real model provider or GitHub repository was used, and no conclusion about model quality is drawn.

## How to reproduce

- `npm ci && npm ci --prefix runner --omit=dev --ignore-scripts && npm run check && BOT_REQUIRE_PI=1 npm test`. CI runs the same, so the real Pi test cannot silently skip there.
- `npm run test:pi:docker` builds the control plane, manager and project computer from the checkout under image tags of its own, starts them as a separate Compose project on ports 18871/18872/18874 and removes that project's containers, networks, volumes and images afterwards. Results go to `.tmp/pi-controller-docker/` (`evidence.json`, screenshots).

## Limits

- No real model or real GitHub repository was used. The user scenario on the test organization needs a deployment of this change.
- Pi runs the project controller and the review/Actions entry executor. Worker roles of the development and request teams stay on `native`/`process`; the three CLI harnesses are later issues.
- Native resume covers a session that is still running after a control-plane crash. A graceful stop (`SIGTERM`, `stop_grace_period`) lets the run finish instead; a session that already ended is rebuilt from task records, reusing completed delegations.
- Scheduled entries that consume #166 tasks are not part of this change.
- The existing `npm run test:agent` journey was not run for this change: its cleanup uses `docker compose down --volumes`.
